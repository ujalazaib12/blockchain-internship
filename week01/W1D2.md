Day 2 Task: The Cryptography Behind Blockchain
Hashing
A hash is like a fingerprint for data. You put any piece of information into a hashing function and it spits out a fixed length string of letters and numbers. Same input always gives the same output. Even a tiny change in the input completely changes the output. This is used to check if data has been tampered with, because if even one letter changes, the fingerprint changes completely.

Public and Private Keys
Every user has two keys that work as a pair. The public key is like your bank account number, you can share it with anyone so they can send you money. The private key is like your ATM PIN, it must stay secret because it proves the account is yours and lets you access or spend what's inside. In blockchain, your wallet address comes from your public key, and your private key is what lets you approve and sign transactions.

Digital Signatures
When you send a transaction, you sign it with your private key. This signature proves two things. First, that the transaction really came from you and not someone pretending to be you. Second, that nobody changed the transaction after you signed it. Anyone can use your public key to check that the signature is valid, but only you could have created it because only you have the private key.

How Blocks Link Into a Chain
Each block contains a group of transactions plus the hash of the previous block. So block two stores the fingerprint of block one, block three stores the fingerprint of block two, and so on. This is what makes it a chain.

Why This Makes It Immutable
If someone tries to secretly change a transaction in an old block, the hash of that block changes completely. But the next block still stores the old hash, so it will no longer match. To fix this, the attacker would have to change every single block after it too, and redo that work faster than the entire network combined. This is practically impossible, which is why the data is considered safe from being quietly altered.
